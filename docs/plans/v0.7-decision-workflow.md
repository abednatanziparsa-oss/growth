# v0.7 Decision & Workflow Engines — Implementation Plan

> Decided 2026-08-20 (Parsa + Growth). Status: **Complete 2026-08-26** — DecisionEngine, WorkflowEngine (engine + YAML loader + CLI + persistence), and a review-loop example all shipped.

## Context

v0.6 shipped AI integration (LLMChat port + OpenAICompatibleChat + AiInterpreter +
PDF/AI documents). v0.7 turns the existing Noop `DecisionEngine` and
`WorkflowEngine` ports into real, advisory capabilities.

- **Advisory-only** (ADR-0002): the Decision Engine never mutates domain state —
  it produces `DecisionArtifact` recommendations that a human (or the Workflow
  Engine) accepts and forwards to a use case.
- **Offline-first**: the Decision Engine is deterministic (heuristic), not
  LLM-dependent. The Workflow Engine runs steps (use cases), optionally with
  LLM-assisted steps later.

## Scope

### 1. DecisionEngine (heuristic) — first ✅ shipped 2026-08-20
- Real `HeuristicDecisionEngine` behind the `DecisionEngine` port, reading the
  task tree via `TaskRepository`.
- Queries:
  - `next_action` — highest-priority actionable incomplete task (leaf-first).
  - `blockers` — overdue incomplete tasks, sorted by due date.
  - `priority_sort` — all incomplete tasks sorted by priority → due → effort.
- CLI: `growth decide next-action|blockers|sort`.

### 2. WorkflowEngine (declarative) — next ✅ shipped 2026-08-26
- Engine core (`DeclarativeWorkflowEngine`), YAML loader, CLI `workflow register|run|list`, persistence via `~/.growth/workflows` + auto-load.
- Declarative YAML workflow definitions (trigger + ordered use-case steps).
- Dry-run, cancellation, per-run logging. Steps call use cases, never raw
  domain/infrastructure.

### 3. Review loop — after ✅ shipped as example 2026-08-26
- `examples/workflows/review-loop.yaml` wires execution → review (reminder-sweep, export-ics, decision queries).
- Planning (AiInterpreter, needs LLM) and improvement (advisory) remain for LLM-assisted workflows.
- planning → execution → review → improvement flow, wired through WorkflowEngine.

## Decisions

- DecisionEngine is **deterministic** (no LLM) — recommendations must be
  reproducible and free. LLM-assisted decisions (later) wrap around this core.
- Recommendation payloads are plain dicts (task_id/title/priority/due_at/
  estimated_minutes), not domain objects — keeps the advisory boundary honest.
